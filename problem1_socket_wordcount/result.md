# 题目一运行结果（result.md）

> 以下结果均为本机实际运行产出（Windows 11 + JDK 17.0.20.1 + Spark 4.2.0 + Python 3.15）。
> 数据源使用项目自带 `mock_data_server.py`（每 0.5 秒发送一句英文），替代 Linux 的 `nc -lk 9999`。

运行环境说明：控制台表格默认只展示前 20 行（Spark console sink 的默认行为），完整结果保存在 `docs/` 与输出目录中。

---

## 问题 1：全量词频统计（Complete 模式 + 10 秒触发）

**执行命令**

```bash
# 终端1：造数据
python mock_data_server.py --interval 0.5
# 终端2：运行作业
python wordcount.py --mode basic --runtime 55
```

**实际输出（节选 Batch 0 ~ Batch 5）**

```text
-------------------------------------------
Batch: 0
-------------------------------------------
+----+-----+
|word|count|
+----+-----+
+----+-----+

-------------------------------------------
Batch: 3
-------------------------------------------
+----------+-----+
|word      |count|
+----------+-----+
|era       |11   |
|love      |7    |
|easy      |5    |
|learning  |6    |
|hello     |2    |
|spark     |10   |
|is        |5    |
|we        |6    |
|general   |3    |
|engine    |5    |
|structured|5    |
|processing|16   |
|stream    |16   |

```

**结果解读**

1. 每 10 秒产生一个 `Batch`（0 → 5，共 6 个微批），符合 `trigger(processingTime="10 seconds")`；
2. `Batch: 0` 为空表，因为第一批触发时数据尚未进入 socket 缓冲区；
3. **Complete 模式的特征**：每批都打印**迄今为止的全量词频**，旧词计数持续累加（如 `hello` 从 1 → 2 → 3），而不是只打印本批新增；
4. 词表中包含 2 字母（`is`/`we`）与长词（`learning`/`structured`/`processing`/`technology`），说明问题 1 未做长度过滤。

## 问题 2：只统计 3-5 个字母的单词

**执行命令**

```bash
python wordcount.py --mode filter --runtime 55
```

**实际输出（Batch 4，全量 20 行）**

```text
-------------------------------------------
Batch: 4
-------------------------------------------
+-----+-----+
|word |count|
+-----+-----+
|era  |4    |
|love |5    |
|easy |3    |
|hello|6    |
|cat  |6    |
|spark|31   |
|with |8    |
|are  |9    |
|makes|3    |
|real |8    |
|cloud|4    |
|sat  |6    |
|clean|5    |
|mat  |6    |
|and  |16   |
|time |8    |
|the  |30   |
|big  |14   |
|world|11   |
|job  |9    |
+-----+-----+
```

**结果解读**

| 单词 | 长度 | 问题1 | 问题2（过滤后） |
| --- | --- | --- | --- |
| `spark` / `hello` / `world` / `cloud` | 3-5 | 有 | 保留 |
| `is` / `we` / `us` | 2 | 有 | **被过滤** |
| `learning`（8）、`structured`（10）、`processing`（10）、`technology`（10）、`general`（7）、`pipeline`（8） | >5 | 有 | **被过滤** |
| `the` / `and` / `are` / `big` / `cat` | 3 | 有 | 保留（长度合法） |

过滤条件为 `length(col("word")).between(3, 5)`，位置在 `explode` 之后、`groupBy` 之前，因此不会为被过滤的词维护聚合状态。

## 问题 3：Parquet 文件接收器 + 检查点

**执行命令**

```bash
python wordcount.py --mode parquet --runtime 60 \
  --output D:/tmp/wordcount_output \
  --checkpoint D:/tmp/wordcount_checkpoint
```

> 作业要求的是 `/tmp/wordcount_output`（Linux 路径）；Windows 本地调试时用 `--output` 覆盖为可写目录，代码默认值仍是 `/tmp/wordcount_output`。

**输出目录结构（实际生成 3 个批次、共 19 个 parquet 文件）**

```text
wordcount_output/
├── _spark_metadata/                    # 文件 sink 的提交日志（保证追加可见性）
├── part-00000-...-c000.snappy.parquet
├── part-00000-...-c000.snappy.parquet
└── ...                                 # 每个微批生成一批文件（按 shuffle 分区数切分）

wordcount_checkpoint/
├── commits/                            # 已成功提交的批次
├── offsets/                            # 每个批次消费到的位点
└── state/0/0..7/                       # 聚合中间状态（按分区存储）
```

**结果解读**

1. 统计口径已从"全量累计词频"改为**10 秒事件时间窗口内的词频**，这是 File Sink 只支持 Append 模式的必然结果；
2. `withWatermark("event_time", "20 seconds")` 让窗口结束后再等 20 秒，确认无更早数据才追加输出并清理状态；
3. 输出包含 `window_start / window_end / word / count` 四列，共 42 行，覆盖 2 个已定型窗口；
4. 仍保留问题 2 的 3-5 字母过滤（`is`、`structured`、`technology` 等均未出现）；
5. 检查点目录包含 `commits/`、`offsets/`、`state/` 三类数据，删除检查点会导致从头开始消费；保留检查点则重启自动续跑、不重复处理已提交批次。
